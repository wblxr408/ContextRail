# Spec Delta

## Purpose

为已经绑定的个人任务提供原生上下文辅助：会话压缩后恢复当前要求和读取入口，在处理文件时显示有出处的历史。所有补充都保留精确任务、要求版本和来源身份，帮助用户继续工作而不改变原有任务权威或工具权限。

## Delivery Scope

本批聚焦用户正在使用的 Codex/Claude 适用主会话事件，优先保留上游处理代码并接本项目接口。补注入与文件历史不依赖完整界面；更多客户端后置。

## ADDED Requirements

### Requirement: 压缩后的精确补注入
系统 SHALL 根据明确绑定的主会话压缩事件登记待补充状态，在后续支持返回上下文的事件中提供当前任务入口；普通重放不得反复补入同一来源版本。

#### Scenario: 下一可用事件补充一次
- **WHEN** 已绑定主会话收到压缩事件且下一事件允许返回上下文
- **THEN** 返回当前有效要求、最后纠正与精确回读入口，并区分 pending、prepared 和 returned 记录

#### Scenario: 必需来源失效
- **WHEN** 待补注入的精确快照已失效或必需材料无法装入
- **THEN** 系统明确报告当前性或预算缺口，不以同项目最新快照替代，也不声称补注入成功

### Requirement: 文件相关历史
系统 SHALL 仅为明确归属当前工作区的文件提供有界历史，保留来源和版本，并允许在同一会话出现新来源版本后再次补充。

#### Scenario: 相同来源重复读取
- **WHEN** 同一绑定会话重复读取同一文件且相关来源版本没有变化
- **THEN** 系统抑制重复历史正文，原文件读取和精确回读能力仍可用

#### Scenario: 文件历史查询失败
- **WHEN** 可选文件历史来源不可用或路径无法可靠识别
- **THEN** 系统保留普通读取，显示适用的历史缺口，不推断其他工作区文件身份或批准工具执行

### Requirement: 搜索结果的连续回读
系统 SHALL 允许从已有三源查询结果进入所选命中的时间邻域与批量详情，所有操作保留独立来源、精确身份和逐项失败状态。

#### Scenario: 批量详情部分失效
- **WHEN** 多个选定结果中只有部分来源仍可读取
- **THEN** 可用项返回原文引用，失效项返回独立原因，显示预览不冒称完整原文

### Requirement: 无模型路径
系统 SHALL 在模型不可用时保留显式用户记录、原文回读和确定性简报入口，并说明未完成的归纳或索引。

#### Scenario: 归纳不可用时保存纠正
- **WHEN** 用户明确记录有出处的纠正而模型归纳无法调用
- **THEN** 原记录可保存和回读，状态说明归纳未完成，不为同一来源重放创建重复业务记录

### Requirement: 保留原有控制边界
系统 MUST 继续以 Bridge 要求和原任务版本判断当前性，不因可选历史补充而改变授权、租约、必需材料预算或原生工具确认。

#### Scenario: 可选历史不足以满足必需要求
- **WHEN** 文件历史存在但当前必需要求无法恢复
- **THEN** 系统明确区分两种状态，不以历史查询成功替代任务恢复完成
