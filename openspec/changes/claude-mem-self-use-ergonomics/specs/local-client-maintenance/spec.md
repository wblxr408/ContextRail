# Spec Delta

## Purpose

让单机用户理解当前上下文与记忆链路的实际状态，并能维护自己安装的客户端接线和数据资产。维护能力沿用现有来源、预算、所有权和保护规则，保留失败恢复材料，避免配置升级或状态展示给出超过实际观测的结论。

## Delivery Scope

稳定性与故障解释先服务现有 Codex/Claude、聊天、CLI/MCP。只读生效配置不依赖完整设置页面；受管配置回滚使用已有备份。全面数据备份恢复扩展与设置编辑页后置。

## ADDED Requirements

### Requirement: 观察状态的原因解释
系统 SHALL 从原状态来源显示采集、学习、延期、索引与上下文准备阶段，附带已观察时间、原因及适用操作；缺失观测保留未知。

#### Scenario: 资源或额度暂停
- **WHEN** 原队列明确记录资源退避或额度延期
- **THEN** 系统显示延期原因和原恢复条件，不显示为记录丢失，也不建议以重启清除额度限制

### Requirement: 生效配置与预览
系统 SHALL 通过现有入口显示有效配置值及其来源、允许的作用域和生效时机；上下文预览必须标记为本次生成视图。

#### Scenario: 配置秘密被遮罩
- **WHEN** 用户保存只改变普通字段的配置页面
- **THEN** 仅普通字段更新，遮罩内容不覆盖真实秘密，既有个人模型与账号不被隐式切换

#### Scenario: 打开上下文预览
- **WHEN** 用户查看某精确任务版本的上下文预览
- **THEN** 系统显示必需材料、可选材料和省略情况，不把该预览登记为历史模型输入

### Requirement: 受管配置的可恢复更新
系统 SHALL 仅迁移或删除有本工具归属证据的配置项，保留其他内容，并在多文件更新失败时提供恢复状态。

#### Scenario: 用户修改了受管项
- **WHEN** 已安装项与记录版本不符且包含用户修改
- **THEN** 系统报告冲突，保留用户内容和旧恢复材料，不按名称猜测覆盖

#### Scenario: 更新中途失败
- **WHEN** 多个配置文件只有部分替换成功
- **THEN** 系统恢复已修改部分或明确保留恢复材料与剩余操作，不报告整次成功

#### Scenario: 精确卸载
- **WHEN** 用户移除本工具的项目接线
- **THEN** 只移除确认归属且未产生冲突的条目，原 Basic Memory、其他 Hook 和用户 trust 状态保持原有控制

### Requirement: 有界备份与恢复
当全面数据备份恢复扩展显式启用时，系统 SHALL 区分权威知识、任务数据库、配置、可重建索引和不可复用的活动权限，在明确范围内生成备份并保留恢复失败时的原状态。

#### Scenario: 活动写入未停止
- **WHEN** 请求恢复仍被当前写入者使用的数据
- **THEN** 系统拒绝替换并说明具体冲突，不强制夺取租约或把旧权限当作有效授权

#### Scenario: 恢复后索引待重建
- **WHEN** 原文与任务已恢复而派生索引尚未重建
- **THEN** 系统明确显示覆盖缺口，保留直接原文读取，不把索引空结果解释为原数据不存在

### Requirement: Windows 路径与失败恢复
系统 SHALL 在含中文、空格及不同解释器布局的 Windows 环境中使用明确参数和范围；占用、链接或不支持路径造成失败时保留可解释状态。

#### Scenario: 文件占用导致替换失败
- **WHEN** 受管配置或恢复材料因 Windows 文件占用无法完成替换
- **THEN** 系统有界结束操作并提供恢复位置，不无限重试、静默清理原件或报告成功
