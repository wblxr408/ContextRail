## 1. 大领域现状（Big Field）

**领域**：LLM agent 流水线中的**跨模型/跨 agent 上下文继承**。

现代 agent 系统普遍不由单一模型跑完全程，而是在**切换边界**上交接状态：

1. **成本/能力路由**：便宜模型处理简单步，难步升级到强模型（FrugalGPT、RouteLLM、AutoMix 一系）。
2. **多 agent 编排**：planner→executor→critic 等角色间传递中间推理与"事实"。
3. **长任务压缩/重启**：上下文超预算时摘要压缩后交给下一段续写（本项目 ContextRail 的核心场景）。

这三种切换的共同结构：**接收方模型必须在一段"不是它自己创作"的轨迹（reasoning trace + 中间事实 + 工具结果）之上继续工作。** 大领域已确立两件事：

- **切换真实发生且被继承的前缀有因果影响**（Switching Drift / Performance Drift 证明 "prefix influence" 是可量化的因果杠杆）。
- **继承整条弱轨迹在升级场景是净损失**（Handoff Tax：全轨迹升级只挽回不到一半能力差距还多付成本；减少弱模型轨迹反而提升升级质量）。

> 这两篇是本题最贴合的"结构动机"，但**均为 [PREPRINT]**（2608.24358 / 2603.03111），且**只测 cost/quality，abstract 无 adversarial 字样**。它们证明"结构存在且良性有损"，把它变成安全问题是本题的活。

## 2. 小领域现状与 GAP

把大领域切成四个与本题直接相邻的小领域，逐一给现状 + 它到本题还差什么。

### 2.1 子领域一：模型切换 / 级联路由（定义"升级"这一场景）

**现状（均 ✓核实 venue）**：路由/级联是本题威胁得以成立的**结构前提**——系统故意在模型间切换。
- **RouteLLM**（Ong et al., **ICLR'25 poster ✓** iclr.cc/virtual/2025/poster/30737，OpenReview 8sSqNntaMr；正式题名 "Learning to Route LLMs from Preference Data"）：训练二元路由器，把 query 动态发往**强 vs 弱** LLM 权衡成本/质量——**精确定义了本题攻击的那条 weak→strong 升级边界**。
- **FrugalGPT**（Chen, Zaharia, Zou, **TMLR 2024/12 ✓** OpenReview cSimKw5p6R；注：TMLR 是受尊重期刊但非 CCF 榜）：LLM **级联**，从便宜到贵顺序调用、够好即停——确立"流水线串接模型、把中间输出前传"这一继承前提。
- **AutoMix**（Aggarwal et al., **NeurIPS'24 ✓** poster 94293）：按小模型对**自身输出的自校验**决定是否升级到大模型——**升级由弱模型的自我报告/轨迹触发**，直接关联"被攻陷弱模型操纵升级"。
- **When Does Confidence-Based Cascade Deferral Suffice?**（Jitkrittum et al., **NeurIPS'23 ✓** OpenReview 4KZhZJSPYU）：级联 deferral 的理论分析，证明 deferral 决策可被误导——为"升级决策本身是攻击面"提供理论地基。
- **Mixture-of-Agents**（Wang et al., **ICLR'25 poster ✓** poster 28787）：每层 agent 把**上一层输出**当辅助输入聚合——**直接演示轨迹/输出跨模型边界被继承**，多模型版的继承威胁。
- **ReAct**（Yao et al., **ICLR'23 oral ✓** OpenReview WE_vluYUL-X）：交错 Thought/Action/Observation 构成显式推理轨迹——**定义了"被交接的轨迹对象"本身**。
- **Reflexion**（Shinn et al., **NeurIPS'23 ✓**）：自写反思存入 episodic memory 引导后续尝试——自产文本持久化并再利用的继承向量。
- **Toolformer**（Schick et al., **NeurIPS'23 ✓** OpenReview Yacmpz84TH）：LM 自监督学会内联发 API 调用——工具结果（可被攻击者影响的外部内容）成为被前传的轨迹的一部分。
- **Generative Agents**（Park et al., **UIST'23 ✓** ACM DL 10.1145/3586183.3606763）：memory stream 长期存储经验并反馈行为——继承/累积 agent 记忆的原型架构。
- **RAG**（Lewis et al., **NeurIPS'20 ✓** proceedings）：外部检索内容（非原生、可能被攻击者控制）注入生成上下文——非原生任务真相进入轨迹的机制，正是"只传版本化校验真相"要防的入口。
- [PREPRINT]：**MemGPT**（Packer et al., arXiv 2310.08560，**确认未发表**，用户此前"COLM'24?"猜测不成立）：OS 式分页记忆、自编辑 core memory——结构上极相关（自管持久记忆=可跨会话投毒的轨迹存储），但只作动机、不作基础。

**GAP**：这一系全部把切换当**成本/质量优化**问题——路由决策的输入是 query 难度或模型置信度（AutoMix 甚至就用弱模型的自我报告），**从不把"被继承的轨迹本身"当作对抗输入**。没有任何路由/级联工作问：如果写前缀的那一档是被攻陷的，会怎样？升级边界因此是一个**无人设防的信任传递点**。MoA 证明轨迹确实跨模型边界被继承，却在良性协作设定下——把它当攻击面无人做。

### 2.2 子领域二：上下文 / 轨迹降智机制（威胁模型里"为何有害"那一半）

**现状**：已有大量**已发表（非预印本，均 ✓核实 venue+引用，Semantic Scholar API 2026-09-24 live 取）**工作证明"喂进上下文的内容会压过模型自身先验、并被下游放大"。逐条对应本题威胁模型里"继承轨迹为何有害"的一种机制：
- **Lost in the Middle**（Liu et al., **TACL'24 ✓** Anthology 2024.tacl-1.9，~5.1k 引）：检索准确率随位置呈 U 形，长上下文**中部**信息被严重低用。→ 长的继承轨迹把版本化真相埋进中部（被低估），而攻击者最新注入内容落在 recency 偏好的尾部。**位置/长度**这一害。
- **LLMs Can Be Easily Distracted by Irrelevant Context**（Shi et al., **ICML'23 ✓** PMLR v202，~1.2k 引）：加入无关句即显著拉低推理，模型无法可靠忽略离题内容。→ 继承轨迹里塞入"看似合理但无关"的中间事实，即使无显式恶意也降智——**非原生上下文的体量本身**就是攻击面。**干扰**这一害。
- **How LM Hallucinations Can Snowball**（Zhang et al., **ICML'24 ✓** PMLR v235，~470 引）：早期已下承诺的错误锚定后续全部步骤，产生本可自查出的连锁错误（GPT-4 能认出自己 87% 的滚雪球错误）。→ **继承的关键**：弱上游的早期错误变成强下游过度承诺并"发扬"而非纠正的锚点——正是"续写非原生轨迹 vs 从干净真相起步"危险性的核心。**复合/雪球**这一害。
- **Why Exposure Bias Matters（Imitation Learning 视角的误差累积）**（Arora et al., **Findings of ACL'22 ✓** Anthology 2022.findings-acl.58，~150 引）：从模仿学习形式化"条件于自身已生成 token 会沿序列累积误差"（且困惑度掩盖它）。→ **自条件化/误差传播的理论骨架**："模型条件于被供给的先验轨迹会继承并放大其扭曲"——本题攻击所利用、防御所切断的机制。
- **Towards Understanding Sycophancy**（Sharma et al., Anthropic, **ICLR'24 ✓** OpenReview tvhaxkMKAn，~1.4k 引）：RLHF 助手系统性附和输入中陈述的观点/断言，重同意轻正确。→ 若继承轨迹断言了立场或伪造前提，强模型**倾向附和并在其上构建**而非质疑——植入的中间"事实"自我强化，除非丢弃轨迹。**顺从**这一害。
- **Adaptive Chameleon or Stubborn Sloth（知识冲突行为）**（Xie et al., **ICLR'24 Spotlight ✓** DBLP conf/iclr/Xie0CL024，~400 引）：LLM 高度接纳连贯的外部证据、即便与参数化知识矛盾，且框得越有说服力越接纳。→ **现代最强的 context-vs-parametric 结果**：强下游会为一条精心构造的冲突断言放弃正确内部知识——伪造"事实"武器化的直接机制。
- **Entity-Based Knowledge Conflicts in QA**（Longpre et al., **EMNLP'21 ✓** Anthology 2021.emnlp-main.565，~450 引）：提出 context-vs-parametric 冲突的替换框架，模型常"幻觉而非阅读"、过度信任所给段落。→ **知识冲突这一支的起源性、最高引框架**，与 Xie et al. 配对引用。

**GAP**：这些都在**良性/自然**设定下测量"长或杂的上下文有害"。**没有工作把"被继承的轨迹"当作攻击者可控变量**去问：攻击者精心构造的前缀能以多高成功率驱动下游更强模型做禁止动作？降智机制提供了"为何继承有害"的六种机理地基（位置/干扰/雪球/自条件化/顺从/知识冲突），但**对抗版的量化是空白**——本题正是把这些良性机理接上对抗框架。

### 2.3 子领域三：prompt injection 攻击与防御（最近的攻击原语）

**现状（攻击/基准，均 ✓核实 venue）**：本题的攻击基元与 indirect prompt injection 同源——不可信内容进入可信上下文后被当指令执行。
- **Greshake et al.**"Not what you've signed up for"（**AISec@CCS'23 ✓** ACM DL 10.1145/3605764.3623985）：首次命名并演示 *indirect* prompt injection——"不可信内容进上下文即被当指令执行"的规范性证明。本题的继承轨迹正是这种"活在可信上下文里的外来内容"。
- **InjecAgent**（Zhan et al., **ACL Findings'24 ✓** Anthology 2024.findings-acl.624）：1054 例（17 用户工具 × 62 攻击工具），测 agent 是否服从从**工具输出**注入的指令；30 个 agent 均可被攻破。**但它在实时工具调用步注入，NOT 跨模型切换边界**——伪造工具结果嵌入继承轨迹正是它的向量，但它不覆盖轨迹继承。
- **AgentDojo**（Debenedetti et al., **NeurIPS'24 D&B ✓** proceedings hash 97091a…，SafeBench 一等奖）：动态 agent 环境（97 任务/629 安全用例），攻防同评。**威胁模型是"单 agent 处理不可信工具数据"，无"弱模型把轨迹交给强模型"概念**——测症状（agent 被劫持）而非本题隔离的切换边界机制。可作评测骨架。
- **Liu et al.**"Formalizing and Benchmarking Prompt Injection Attacks and Defenses"（**USENIX Security'24 ✓** usenix.org presentation/liu-yupei）：把注入形式化为 target+injected 指令/数据的组合（5 攻击 × 10 防御 × 10 LLM × 7 任务）。**本题应引它作定义锚**——但它的形式模型把注入当"一个 prompt 内被污染的数据"，**不建模"整条带自身信任状态的先验轨迹被继承"的边界**，那正是本题要形式化的 gap。

**现状（防御）**——**关键：这些防御全部是单步、边界内的分离防御，无一测试信任标签能否扛过一次模型切换/压缩**：
- **StruQ**（Chen et al., **USENIX Security'25 ✓** usenix.org presentation/chen-sizhe）：微调 + 安全前端把 prompt vs data 分两通道，data 通道文本不被执行。**失效点**：假设推理时有干净的 prompt-vs-data 划分；继承轨迹**既不是"指令"也不是"外部数据"**，它作为可信推理上下文进入——StruQ 依赖的通道标签对外来轨迹根本不存在。
- **SecAlign**（Chen et al., **CCS'25 ✓（二手源确认，非 ACM DL proceedings 直核，高置信但注明）** arXiv 2410.05451）：偏好优化（DPO 式）把"服从注入指令"压到 <10%。**失效点**：切换时强模型继承的内容已被框成"它自己的先验推理/可信上下文"，而非可拒绝的显式注入指令——SecAlign 训练的偏好信号（外部数据试图发指令）在"看似自产"的轨迹上不触发。单轮训练假设。
- **ASIDE**（Zverev et al., **ICLR'26 poster ✓（已接收，camera-ready 未进 proceedings，引作"to appear"）** arXiv 2503.10566）：对 data-token embedding 做正交旋转，使指令/数据表示可分。**失效点**：同 StruQ/SecAlign——预设每个 token 输入时即带 instruction-or-data 标签；继承轨迹**跨切换不携带 per-token provenance**，ASIDE 无法把外来推理标成"data"，因为它经 instruction/history 路径到达。
- **Zverev et al.**"Can LLMs Separate Instructions From Data?"（**ICLR'25 ✓** proceedings hash a77eadda…）：形式化并度量指令-数据分离（SEP 数据集），**证明所有受测 LLM 都无法可靠分离二者**。**这是本题最强的支撑证据之一**：既然模型在**单个 prompt 内**都分不清指令与数据，跨一条被继承的轨迹就更分不清——标签级防御（StruQ/SecAlign/ASIDE/Spotlighting）本质脆弱，"信任标签不可假定存活"（C1）有了 impossibility 式地基。
- **Spotlighting**（Hines et al., **[PREPRINT]** arXiv 2403.14720，无 peer-reviewed venue）：输入变换（分隔/数据标记/编码）给不可信内容打 provenance 标记。**明确依赖"信任标记随文本一起走"**——切换/压缩边界上标记被剥离或未对继承轨迹重新施加，正是本题防御针对的"假设标签存活"失效点。**绝佳反例**，但预印本不作基础。
- **CaMeL**"Defeating Prompt Injections by Design"（Debenedetti et al., **[PREPRINT]/in-press**：作者页称 SaTML'26 接收，proceedings 未出；SaTML 是较小 IEEE 会、非 CCF-A；arXiv 2503.18813）：能力/控制流层，特权 LLM 对不可信数据发代码、自定义解释器强制数据流策略。**最强的设计级隔离、也是本题哲学上最近的邻居**——但 CaMeL 隔离不可信**数据**、仍让其流经系统，且假设一个**可信的顶层用户 query**，**不处理"被攻陷的上游模型轨迹被当可信推理继承"**——那正是本题防御填的洞。预印本/in-press，不作基础但须显式区分。

**GAP**：所有防御都假设**信任边界在单次推理内是稳定的**——它们在"这一步"里区分指令与数据（Zverev ICLR'25 甚至证明连这一步都做不可靠）。**没有一篇追问：当上下文经过一次模型切换或压缩重编码后，这些信任标签/通道分离是否还存活？** 一旦弱模型把注入内容"洗"进它写的轨迹，下游强模型看到的是一段"看起来是自己队友产出的可信推理"，分离防御赖以工作的"这是外部数据"标记已经丢失。这正是本题攻击面之所以逃出现有防御的机理。

### 2.4 子领域四：记忆 / RAG 投毒 + 多 agent 传播（轨迹即 payload、跨边界传播）

**现状**——这是最贴近"轨迹本身即攻击载荷"的一系，本轮 live 核实质量最高：
- **Poisoning Retrieval Corpora**（Zhong et al., **EMNLP'23 ✓核实** Anthology 2023.emnlp-main.849）：<500 条对抗 passage 即被多查询检索命中——"被检索的语料本身是攻击面"的地基。
- **PoisonedRAG**（Zou et al., **USENIX Security'25 ✓核实**，CCF-A）：每问注入 ~5 条恶意文本 → 百万文档库上 90% 攻击成功。**"继承的检索事实即 payload"最强先例。**
- **AgentPoison**（Chen et al., **NeurIPS'24 ✓核实**，CCF-A）：优化后门触发器投毒 agent 长期记忆/RAG，<0.1% 投毒率 >80% ASR、无需微调——**"持久化 agent 记忆是可被跨会话滥用的写通道"直接先例**。
- **MINJA / Memory Injection via Query-Only**（Dong et al., **NeurIPS'25 ✓核实**）：仅靠正常 query 就能投毒记忆库（~95% 注入 / ~70% ASR）——**普通用户即可触达该通道**，强化"升级时必须丢弃/校验继承记忆"。
- **BadChain**（Xiang et al., **ICLR'24 ✓核实**，CCF-A）：往 CoT 里插恶意后门步，且**越强的推理模型越易中招（最高 97% ASR）**。**"推理轨迹本身即 payload"的最佳先例，且"更强下游模型更脆弱"精确映射本题升级设定。**
- **Poisoning LM During Instruction Tuning**（Wan et al., **ICML'23 ✓核实**，CCF-A）：~100 条投毒样本经触发词污染指令模型——"可信方本身可能已被预污染"的兜底。
- **Agent Smith**（Gu et al., **ICML'24 ✓核实**，CCF-A）：单张对抗图片经共享记忆在多 agent 群体中指数传播——**"腐蚀跨 agent 边界传播"的经典先例**。
- **Flooding Spread of Manipulated Knowledge**（Zhang et al., **Science China Info Sci ✓核实**，SCI 期刊）：反事实知识无需显式操纵即在 agent 间扩散——"下游继承并再传播"的传播先例。
- 近邻：**Prompt Infection**（Lee & Tiwari，**ESORICS'25 SECAI workshop ✓核实**，Springer LNCS；注：workshop 非主会，降权当近邻）。
- [PREPRINT]：**BadRAG**（Xue et al., arXiv 2406.00083，未确认接收，单列不作基础）。

**GAP**：投毒一系已牢固证明"持久化/被检索的产物可以是 payload""腐蚀跨 agent 边界传播"。但它们的**攻击通道是记忆库/检索语料/训练数据**，防御手段是投毒检测、鲁棒检索、触发器净化。**没有一篇把"模型切换/升级边界本身"当作攻击面**，也没人提出"**丢弃非原生轨迹**"这一构造式防御——它们要么净化 payload，要么加固检索，都在"保留并清洗"的范式里。BadChain 甚至反向证明"更强下游越危险"，却把它当模型脆弱性、没连到切换架构。

### 2.5 GAP 综合裁决

把四个子领域摆在一起，交叉点是一个**无人认领的空洞**：

| 子领域 | 已确立 | 缺的那一块（本题） |
|---|---|---|
| 切换/路由 | 切换真实发生、前缀有因果影响、全轨迹升级有损 | 从不把被继承轨迹当**对抗输入** |
| 降智机制 | 上下文能压过先验、被下游放大 | 只测**良性**长上下文，无对抗量化 |
| prompt injection | 不可信内容进上下文即可执行；单步分离防御 | 无人测信任标签能否**扛过一次切换/压缩** |
| 记忆/RAG 投毒 | 持久化产物即 payload、跨 agent 传播 | 通道是记忆/语料，**非切换边界**；范式是"清洗"非"丢弃" |

**裁决**：把"弱→强升级切换时继承的非原生轨迹"当作一个**独立攻击面**并给出**丢弃式构造防御**，是 UNCLAIMED 的。四个子领域各出一半证据（切换结构 × 注入原语 × 轨迹即 payload × 降智机理），但没有任何一篇把它们接成"切换边界 = 攻击面"。这是本题的立足点，也是最干净的"结构已存在、只差对抗框架 + 药方"的 gap。

**同时——诚实红线（须在论文里显式写出）**：
- 不 claim 首次发现切换继承（Handoff Tax [PREPRINT] 2608.24358 / Switching Drift [PREPRINT] 2603.03111 的良性结果）。
- 不 claim 发明 prompt injection / 记忆投毒（上面 ✓核实 的一系）。
- 防御 scope 受限：discard **只对升级（弱→强）成立**。降级（强→弱）保留强轨迹常有益（Reasoning Relay / Woodpecker 一系 [PREPRINT]，须复核），别说 universal。

### 2.6 为什么这是真 gap 而非"水"（须写进论文，且能扛审稿人质疑）

"水"（灌水）= 换个词包装已解决的问题、或造一个现实中不存在的问题、或问题真但无法证伪。逐条自证本题不属于这三类。

**判据一：gap 有硬出处，且是"变量缺席"而非"效果不够好"。**
本题不是说现有防御"做得差"，而是说**支撑本题的关键变量在现有实验协议里根本不存在**：
- 子领域三（注入防御 StruQ/SecAlign/CaMeL/Spotlighting）的评测**全是单步**——上下文带标签、当步判定指令 vs 数据。**没有任何一篇的实验设置包含"标签经过一次跨模型序列化→反序列化（切换/压缩）"这一环节**。这是可核查的事实性断言（审稿人可翻它们的评测节反驳我；翻不出即成立），不是主观的"我觉得他们弱"。
- 子领域四（BadChain/PoisonedRAG/AgentPoison ✓核实）的攻击通道是**记忆库/检索语料/训练数据**，**没有一篇的威胁模型把"模型升级切换边界"列为攻击面**。
- 换言之，gap 的证据形式是"在 N 篇相邻工作里检索某变量/某威胁通道，全部缺席"——这是可证伪的空白，不是修辞。

**判据二：问题在现实中真实发生，不是为发论文造的。**
- 级联/路由（FrugalGPT/RouteLLM/AutoMix）是**已部署的省钱架构**，升级切换每天在生产里发生。
- 被继承的前缀**有因果影响**已被 Switching Drift（[PREPRINT] 须复核）量化为 "prefix influence"。
- 注入内容能流入 agent 可信上下文已被 InjecAgent（ACL Findings'24，待核实）实测（ReAct-GPT-4 24% 中招）。
- 三者叠加 = "被攻陷的弱档在真实部署的升级边界上写轨迹"是**现有系统的真实暴露面**，不是假想。

**判据三：反直觉、有区分度，不是"显然成立"的伪命题。**
- 直觉是"升级到更强模型更安全"。BadChain（✓ICLR'24）给出**反直觉**硬证据：更强推理模型对 CoT 后门**更**易感（97% ASR）。本题把这个反常搬到切换边界，命题"升级边界是攻击放大器"**结果方向事先未知**——可能被数据推翻（H3 可证伪）。有被推翻的风险 = 不是水。
- 防御同样有区分度：清洗范式（检测/净化）与丢弃范式（discard-on-switch）会给出**不同**的 ASR，且丢弃范式不依赖"先识别 payload"（C3）。两范式在切换设定下的对照无人做过，且结果可能是丢弃并不更好——这也是可证伪的。

**判据四：可执行、可证伪、可复现。**
- 主指标 ASR、任务成功率、标签存活率、误拒率**全部可跑**（§7），不是只能定性描述的"软"命题。
- 四个挑战各带**可证伪判据**（§3 每条末尾）。任一判据实测不成立，对应挑战即被否，不能事后找补。
- 实验协议基于已有 `contextrail/evaluation/switching.py`，跨厂商（DeepSeek+Kimi）可复现。

**判据五：与最接近的近邻显式可分，novelty 不靠含糊。**
- vs Handoff Tax / Switching Drift（[PREPRINT]）：它们**只测 cost/quality，无 adversarial**；本题加对抗框架并把"减少弱轨迹"从性能启发升级为**命名安全控制**。
- vs Verification-Status Laundering（[PREPRINT]）：它框成**授权语境丢失**；本题是**能力档差 + 轨迹注入**。
- vs Hidden in Thought（[PREPRINT]）：它框成**越狱迁移**；本题是 **tier 升级切换架构**。
- vs 投毒一系（✓核实）：通道是记忆/语料**非切换边界**，范式是"清洗"**非"丢弃"**。
- 这些区分是**机制级**的（攻击通道不同、防御范式不同），不是改个名——审稿人可据此判定不重叠。

**一句话结论（放论文 intro 末尾）**：本题的 gap 由"多个相邻子领域各自缺席同一交叉变量"这一可核查事实界定，问题源于已部署架构的真实暴露面，命题方向事先未知且全部可证伪可复现，与最近近邻可作机制级区分——因此是真 gap，不是灌水。**唯一须严守的诚实红线**：不 claim 发明 handoff 现象或 prompt injection 本身（§9）。

## 3. 具体挑战，及"这些挑战是真 gap 需要解决"的论证

把 gap 落成四个可攻的具体挑战。每个挑战都给出：**是什么 → 为什么现有方案解不了（真 gap 论证）→ 可证伪的判据**。

### C1. 信任标签在切换/压缩后不存活
- **是什么**：分离防御（Spotlighting/StruQ/SecAlign/ASIDE/CaMeL）靠"这段是外部数据"的标记工作。一次模型切换或压缩重编码会把带标记的上下文重写成一段"下游看来是自家队友产出的可信推理"，标记丢失。
- **真 gap 论证**：子领域三所有防御的评测协议**都是单步**——输入带标签、当步判定。没有任何一篇的实验设置里存在"标签经过一次跨模型序列化再反序列化"的环节。这不是"他们做了但效果差"，而是"这个变量在他们的实验里根本不存在"。→ 真空白。**更强的地基**：Zverev et al.（ICLR'25 ✓）已证明 LLM 在**单个 prompt 内**都无法可靠分离指令与数据；那么标签跨一次切换后还能被正确解读，就更无从假定——C1 不是猜想，是已发表不可能性结果的直接推论。
- **判据**：构造带标签上下文 → 过一次切换/压缩 → 测标签存活率与注入成功率。若标签存活率显著 <100% 且注入成功率随之上升，则挑战成立。

### C2. 升级到更强模型反而放大攻击（能力-脆弱性反常）
- **是什么**：直觉是"更强模型更安全"。BadChain（✓ICLR'24）已给出反直觉证据：更强推理模型对 CoT 后门**更**易感（97% ASR）。本题问：在切换设定下，把被投毒轨迹交给更强下游，是否系统性放大而非稀释攻击？
- **真 gap 论证**：BadChain 在**单模型**内测此现象，未连到"切换/升级"架构；切换一系（Handoff Tax）在**良性**下测能力差。两者没被接起来。"升级边界是攻击放大器"这个命题无人测过。→ 真空白。
- **判据**：同一投毒轨迹分别交给 (弱续写) vs (升级到强续写)，比较攻击成功率。若强下游 ASR ≥ 弱下游，则"能力-脆弱性反常在切换边界成立"。

### C3. 没有"丢弃非原生轨迹"这一防御范式的对照
- **是什么**：投毒一系的防御全在"保留并清洗"范式（检测/鲁棒检索/触发器净化）。本题主张一个正交范式：**升级切换时整体丢弃非原生轨迹，只放行版本化、完整性校验过的任务真相**。
- **真 gap 论证**：清洗范式有根本上限——净化器必须先认出恶意内容才能清除，而"看起来像自家可信推理"的投毒轨迹正是设计来躲过识别的（C1）。丢弃范式不依赖识别 payload，只依赖"来源是否原生"这个可密码学锚定的属性。没有工作把这两种范式在切换设定下对照过。→ 真空白 + 有区分度的科学问题。
- **判据**：三臂对比（见 §7）中，丢弃臂在**不识别具体 payload** 的前提下把 ASR 压到近 0，且保住 Handoff Tax 的质量收益，则范式优越性成立。

### C4. 缺少切换边界的对抗基准与指标
- **是什么**：InjecAgent/AgentDojo（✓/待核实）是**单 agent 工具注入**基准，没有"跨模型切换"这一维；Handoff Tax 是**良性**协议。没有现成基准能测"切换边界攻击"。
- **真 gap 论证**：要证明前三个挑战，必须有一个把"切换方向 × 轨迹来源 × 注入位置"作为受控变量的评测协议。它不存在——这本身是须交付的贡献（可复用现有 `contextrail/evaluation/switching.py` 扩展）。
- **判据**：产出一个可复现协议 + 指标集（攻击成功率、任务成功率、质量保持率、标签存活率），跨厂商可跑。

## 4. 我们的解决方法（ContextRail 为可信研究载体）

**核心主张**：把切换边界从"隐式信任传递"改成"显式信任重建"。升级切换时，**非原生轨迹整体丢弃**，只有**版本化、完整性校验过的任务真相**过 handoff 边界。这不是"清洗 payload"，而是"从不让 payload 获得原生身份"。

**ContextRail 的现成机制正好是这套防御的构造载体**：

1. **discard-trace-on-switch = 结构性隔离**。切换时非原生轨迹整体丢弃，只有版本化真相过边界。对应防御 C3 的"丢弃范式"。
2. **不可变、字节精确的证据 store（SHA-256 Ref + scope 隔离）**。过边界的每条"真相"都是内容寻址、可校验来源的；攻击者伪造不出解析进签名快照的字节。对应 C1——信任不靠易丢的标签，靠密码学锚点。
3. **snapshot handoff 生命周期**：`prepare → acknowledge → validate → activate` + epoch fencing。切换是一个带交付回执与代际栅栏的显式协议，而非把 KV/文本裸传。对应 C4——它本身就是可控实验协议的骨架。
4. **span-anchored 摘要 + 依赖闭包成组**：过边界的真相是类型化、成组的（load-whole-or-nothing），使"事实存活而其治理规则被丢"这类残缺态无法发生（这条与 Topic D 共享机制）。

**把 Handoff Tax 的良性质量启发升级成命名的安全控制**：Handoff Tax 说"减少弱轨迹提升升级质量"是个**性能**观察；本题把同一个动作重新命名为**安全控制**（discard-as-defense），并证明它在对抗设定下把攻击成功率压到近 0，同时保住那份质量收益。

**工程增量最小**：可直接复用现有 `contextrail/evaluation/switching.py` 实验框架，只需加一条"对抗前缀"臂。

**防御 scope（诚实）**：discard 只对**升级（弱→强）**成立。降级（强→弱）保留强轨迹常有益，此时防御应切换为"校验来源但不丢弃"。论文须把这条不对称性写死，别 claim universal。

## 5. 威胁者模型（Threat Model）

### 5.1 攻击者能力（Capabilities）
- **控制上游弱/低成本档模型**：或该档已被攻陷、或攻击者能诱导它输出（经 indirect injection 从工具结果/检索内容灌入，见 InjecAgent ✓）。攻击者据此**在升级切换发生前写下一段推理轨迹**。
- **写入通道**：轨迹里可嵌入 (a) 伪装成推理的指令、(b) 投毒的中间"事实"、(c) 伪造的工具调用结果。这三种载荷都有 ✓核实 先例（BadChain 的 CoT 后门 / PoisonedRAG 的投毒事实 / InjecAgent 的工具输出注入）。
- **不需要**直接访问下游强模型的权重、系统提示或 store 的签名密钥。

### 5.2 攻击者目标（Goals）
- 让下游更强模型执行一个禁止动作 / 输出攻击者选定答案 / 采信投毒事实并据此行动。
- 变体（跨边界传播）：使投毒轨迹在被下游继承后**再次传播**给后续 agent（Agent Smith / Flooding Spread ✓ 的传播模式）。

### 5.3 攻击者限制（Assumptions / 密码学锚点）
- 攻击者**伪造不出**能解析进签名快照的 span——这是防御的密码学锚点。store 用 SHA-256 内容寻址 + scope 隔离；攻击者无签名密钥，无法让一条伪造"真相"通过 `validate`。
- 攻击者能污染的是**轨迹（trace）**，不是**已被校验入 store 的版本化真相**。防御的全部力量在于：升级时只放行后者。
- 诚实边界：若攻击者能同时攻陷 store 的写入校验路径（拿到密钥 / 绕过 `_validate_spans`），则超出本威胁模型——那是另一层（供应链/密钥管理），须显式声明 out of scope。

### 5.4 信任边界图（文字版）
```
[上游弱模型/被攻陷]  --写轨迹-->  [切换边界]  --?-->  [下游强模型]
        |                              |
   可注入(trace)                  防御在此:
                              (A)基线: 裸传轨迹 → 下游继承 payload
                              (B)压缩: 摘要后传 → 标签可能丢(C1)
                              (C)ContextRail: 丢轨迹, 只放行
                                  签名校验的版本化真相 → payload 无原生身份
```

### 5.5 与近邻威胁模型的显式区分
- **Verification-Status Laundering**（2609.20211 [PREPRINT] 待核实）：handoff 丢**授权语境**——框成授权洗白，本题是**能力档差 + 轨迹注入**，不同。
- **Hidden in Thought**（2607.15286 [PREPRINT] 待核实）：受损模型 CoT 注入其他模型——框成**越狱迁移**，本题是 **tier 降级/升级切换**架构，不同。
- **Prompt Infection**（✓ ESORICS'25 workshop）：多 agent 自我复制传播——本题聚焦**单次升级边界**的信任重建，传播只是变体。

## 6. 安全模型的形式化建立（Security Model）

给出一个足以支撑评审、又能落到可执行指标的半形式化模型。

### 6.1 对象与记号
- 模型档集合 $M$，能力序 $\prec$（$m_w \prec m_s$ 表示 $m_w$ 弱于 $m_s$）。**升级** = 从 $m_w$ 切到 $m_s$。
- 一次任务状态 = $(T, R)$：$T$ 为**轨迹**（trace，模型自由文本推理 + 中间断言 + 工具结果），$R$ 为**版本化真相集**（store 中内容寻址的 Ref，每个带 SHA-256 与 scope）。
- 切换边界的**传递函数** $\Pi$：把上游状态映射为下游可见上下文 $C = \Pi(T, R)$。三种防御 = 三个不同的 $\Pi$：
  - $\Pi_{\text{base}}(T,R) = T \cup R$（裸传，基线）。
  - $\Pi_{\text{comp}}(T,R) = \text{summarize}(T) \cup R$（压缩）。
  - $\Pi_{\text{rail}}(T,R) = R$（ContextRail：升级时丢 $T$，只放行校验通过的 $R$）。

### 6.2 攻击者模型（形式化 5.1）
- 攻击者选一个投毒轨迹 $T^* $（能力见 §5.1），无法产生任何通过 `validate` 的伪造 Ref，即 $R$ 对攻击者只读、防篡改。
- 攻击成功事件 $\mathsf{Succ}$：下游 $m_s$ 在上下文 $C=\Pi(T^*,R)$ 下产生禁止动作/攻击者目标输出。

### 6.3 安全性质（要证/要测的命题）
- **P1（丢弃完备性）**：对升级切换，$\Pi_{\text{rail}}$ 的输出不含任何 $T$ 派生字节 ⇒ 任何仅存于 $T^*$ 的 payload 不可达下游。可由 `_validate_spans`/snapshot schema 校验**构造性保证**（不是经验概率）。
- **P2（来源不可伪造）**：攻击者使某伪造内容进入 $R$ 的概率 $\le$ 破解 SHA-256/签名的概率（可忽略）。归约到 store 的完整性假设。
- **P3（质量保持）**：$\Pi_{\text{rail}}$ 下的任务成功率 $\ge \Pi_{\text{comp}}$，且接近"良性无攻击"上界（继承 Handoff Tax 的启发）。这是**经验**命题，须实测。
- **P4（不对称 scope）**：P1 的防御价值只在升级成立；降级时 $\Pi_{\text{rail}}$ 会丢有益的强轨迹，故降级须换 $\Pi$。这是模型的**适用边界声明**，不是漏洞。

### 6.4 与"presence≠safety"的对齐
本模型刻意区分**存在性**与**安全性**：$\Pi_{\text{rail}}$ 不宣称"检测出了 payload"，而宣称"payload 从未获得可达下游的原生身份"。这规避了清洗范式"必须先识别才能清除"的根本上限（对应 C3 论证）。

## 7. 实验设计（怎么做实验）

### 7.1 总体设计
在 Handoff Tax / switch-matrix 的良性协议上，**加一条对抗前缀臂**，做**三臂（防御）× 两方向（切换）× 多注入位置**的受控对比。复用 `contextrail/evaluation/switching.py`。

### 7.2 自变量（受控）
- **防御臂 $\Pi$**：(a) $\Pi_{\text{base}}$ 全轨迹继承 / (b) $\Pi_{\text{comp}}$ 压缩 / (c) $\Pi_{\text{rail}}$ 丢轨迹留版本化真相。
- **切换方向**：升级（弱→强，主战场）/ 降级（强→弱，验证 P4 不对称性）。
- **注入类型**（三种载荷，各有 ✓ 先例）：伪装指令 / 投毒中间事实 / 伪造工具结果。
- **注入位置**：轨迹首 / 中 / 尾（呼应 Lost-in-the-Middle 的位置效应）。

### 7.3 因变量（指标）
- **ASR 攻击成功率**（主）：下游产生禁止动作/攻击者目标输出的比例。
- **任务成功率 / 质量保持率**：无攻击基准下 (c) 是否保住 Handoff Tax 收益（守 P3）。
- **标签存活率**：分离防御标签过一次 $\Pi$ 后仍在的比例（专测 C1）。
- **能力-脆弱性斜率**：ASR 随下游模型能力档的变化（测 C2，看是否随能力上升——BadChain 式反常）。
- **误拒率**：合法新鲜轨迹被 (c) 误丢的代价。

### 7.4 假设（可证伪）
- **H1**：$\text{ASR}(\Pi_{\text{rail}}) \approx 0$，且显著 $< \text{ASR}(\Pi_{\text{base}})$，$< \text{ASR}(\Pi_{\text{comp}})$。
- **H2**：$\Pi_{\text{comp}}$ 在注入下**退化**（标签存活率下降 → ASR 回升），即压缩不是安全控制（呼应 C1）。
- **H3**：升级方向下 $\text{ASR}(\Pi_{\text{base}})$ 随下游能力**上升或不降**（C2 反常成立）。
- **H4**：无攻击时 $\text{任务质量}(\Pi_{\text{rail}}) \ge \Pi_{\text{comp}}$，接近全轨迹上界（P3）。

### 7.5 模型与数据
- **跨厂商**：DeepSeek + Kimi（弱/强配对跨厂商，隔离"同源模型互信"混淆）。或**先 DeepSeek 单厂商**（deepseek-chat 弱档 / deepseek-reasoner 强档）通管线，再上跨厂商。**待你定**。
- **任务集**：从 InjecAgent/AgentDojo 借工具注入用例（✓/待核实），改造成"切换边界"版；补 ContextRail 自有的 coding/检索任务。

### 7.6 执行步骤
1. 在 switch-matrix 协议上实现三个 $\Pi$，跑通良性基线（复现 Handoff Tax 质量收益）。
2. 加对抗前缀生成器（三种载荷 × 三种位置）。
3. 跑三臂 × 两方向全矩阵，记录 §7.3 全部指标。
4. 加"in-context 操作者假冒"变体（若与 Topic D 联动），测 (c) 的抗假冒性。
5. 出图：ASR 三臂对比条形图 + 能力-脆弱性斜率折线 + 标签存活率。

### 7.7 消融
- 去掉 store 完整性校验（模拟 P2 假设被破）→ 确认 (c) 的安全性确实来自签名锚点而非丢弃动作本身。
